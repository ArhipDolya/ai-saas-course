# Мій перший Telegram-бот

Це застосунок для відстеження фінансового стану та витрат.

Мінімальний Telegram-бот на aiogram 3.x. Він читає токен тільки зі змінної
середовища `BOT_TOKEN`, вітається на `/start`, показує довідку на `/help` і
зберігає витрати через `/expense` та доходи через `/income`.

## Підготовка

1. Створіть віртуальне середовище та встановіть залежності:

   ```bash
   python3 -m venv .venv
   .venv/bin/python -m pip install --upgrade pip
   .venv/bin/python -m pip install -r requirements.txt
   ```

2. Відкрийте локальний файл `.env` і додайте **новий, перевипущений** токен:

   ```env
   BOT_TOKEN=your_bot_token_here
   ```

   `.env` ігнорується Git, тому секрет не має потрапити до репозиторію.
   Файл `.env.example` містить лише безпечний шаблон.

3. Запустіть бота з кореня проєкту:

   ```bash
   .venv/bin/python -m app.main
   ```

Після повідомлення в терміналі про успішний запуск відкрийте чат зі своїм
ботом у Telegram і надішліть `/start`.

## Запуск у Docker з hot reload

Docker Compose передає `BOT_TOKEN` з локального `.env`, а не з Dockerfile чи
образу. Папка `app/` монтується в контейнер, а `watchfiles` стежить за
Python-файлами: після збереження змін у коді бот автоматично перезапускається.

```bash
docker compose up --build
```

Перший запуск завантажить базовий образ і встановить залежності. Для звичайних
змін у `app/` повторно виконувати команду не потрібно. Якщо ви змінили
`requirements.txt`, `Dockerfile`, `docker-compose.yml` або `.env`, зупиніть
поточний процес і запустіть цю саму команду ще раз.

## API транзакцій

Разом із Telegram-ботом Docker Compose запускає API для майбутнього
вебзастосунку та React dashboard. Документація API буде доступна за адресою
`http://localhost:8001/docs`.

Dashboard доступний за адресою `http://localhost:5173`. Введи свій Telegram ID
у правому верхньому куті сторінки, щоб dashboard завантажив твої дані через
`/api/transactions` і `/api/summary`.

Щоб отримати транзакції конкретного користувача, виконай запит:

```text
GET /api/transactions?telegram_id=<telegram_id>
```

Приклад відповіді:

```json
[
  {
    "id": 1,
    "type": "expense",
    "amount": "120.00",
    "category": "кава",
    "description": "ранкова кава",
    "date": "2026-09-08",
    "created_at": "2026-09-08T10:30:00"
  }
]
```

На цьому етапі `telegram_id` є тимчасовим способом визначити власника даних.
Коли з'явиться вебавторизація, його має замінити ідентифікатор з авторизованої
сесії.

### Створення транзакції з форми

Кнопка «Додати операцію» відкриває форму. Обери користувача через Telegram ID,
заповни поля та натисни «Зберегти». Форма надсилає запит:

```text
POST /api/transactions?telegram_id=<telegram_id>
Content-Type: application/json
```

```json
{
  "type": "expense",
  "amount": "100.00",
  "category": "хліб",
  "description": "Покупка для сніданку",
  "date": "2026-09-10"
}
```

Сервер повертає `201 Created` і JSON з полями `id`, `type`, `amount`,
`category`, `description`, `date`, `created_at` після коміту в Neon.
Форма оновлює таблицю та підсумки через GET-запити. Сума у відповіді є
десятковим рядком, наприклад `"100.00"`.

Правила серверної валідації:

- `type`: лише `income` або `expense`.
- `amount`: від `0.01` до `9999999999.99`, не більше двох знаків після коми.
  Приймається JSON-число або десятковий рядок; кома в рядку також підтримується.
- `category`: від 1 до 100 символів після нормалізації пробілів.
- `description`: необов'язковий опис до 255 символів; порожній текст стає `null`.
- `date`: необов'язкова дата `YYYY-MM-DD`, від `2000-01-01` до поточного дня
  за `Europe/Kyiv`. Пропущене поле, `null` або порожній рядок означає сьогодні.

Некоректні дані повертають `422` з помилками полів; помилка запису до БД -
`503` з повідомленням. При помилці форма зберігає введені значення.
Під час запиту повторне натискання «Зберегти» заблоковано.

Дата операції зберігається в `transactions.transaction_date`, а `created_at`
залишається часом фактичного створення запису. Перед запуском оновленої версії
на наявній БД один раз виконай цю міграцію (для нової порожньої БД таблиці
створюються під час старту):

```bash
docker compose exec api python -m app.migrate_transaction_date
```

Міграція заповнює дату старих операцій з `created_at` і допускає повторний
запуск. Вона не видаляє записи. Якщо сервіси ще не запущені:

```bash
docker compose run --rm --no-deps api python -m app.migrate_transaction_date
docker compose up --build
```

### Видалення транзакції

У рядку операції натисни «Видалити», потім «Підтвердити». «Скасувати»
закриває підтвердження без запиту до сервера. Після підтвердження форма надсилає:

```text
DELETE /api/transactions/{id}?telegram_id=<telegram_id>
```

Сервер видаляє лише транзакцію з указаним ID, яка належить цьому `telegram_id`.
Користувач і категорія залишаються в БД. Відповіді:

- `204 No Content` - видалення закомічене, тіло відповіді порожнє.
- `404` - транзакції немає або вона належить іншому користувачу.
- `422` - некоректний чи відсутній ідентифікатор.
- `503` - помилка БД; транзакція відкочується.

Після успіху рядок зникає, а список, картки та діаграма оновлюються через GET.
При помилці відображається повідомлення. Під час запиту повторне підтвердження
та зміна користувача заблоковані. Для цієї функції міграція БД не потрібна.

## Підсумок фінансів

Ендпоінт `GET /api/summary?telegram_id=<telegram_id>` повертає суми для
майбутнього dashboard:

```json
{
  "total_income": "0.00",
  "total_expense": "120.00",
  "balance": "-120.00"
}
```

`total_income` підсумовує операції `income`, `total_expense` - `expense`,
а `balance` дорівнює різниці доходів і витрат для обраного користувача.

## Перевірка підключення до Neon

Додайте до локального `.env` змінну `DATABASE_URL` із connection string Neon.
Скрипт `app/check_connection_to_db.py` створює синхронне з'єднання через
SQLAlchemy та драйвер `psycopg` 3, виконує `SELECT 1` і завершується з кодом
`0` за успіху або `1` за помилки.

Після зміни `requirements.txt` зберіть образ, а потім виконайте разову
перевірку без запуску Telegram-бота:

```bash
docker compose build && docker compose run --rm --no-deps bot python -m app.check_connection_to_db
```

## Додавання фінансової операції

Під час старту бот створює відсутні таблиці `users`, `categories` і
`transactions` у Neon. Щоб додати витрату або дохід, надішліть боту:

```text
/expense 120 кава
/income 50000 зарплата
```

Щоб додати опис, відділіть його символом `|`:

```text
/expense 120 кава | ранкова кава
/income 50000 зарплата | вереснева виплата
```

Після успішного коміту в базу бот відповість із сумою, категорією та описом,
якщо його передано. Сума має бути додатною і містити не більше двох знаків
після коми. Категорія може складатися з кількох слів.

Після оновлення до версії з доходами та описами один раз виконайте міграцію:

```bash
docker compose run --rm --no-deps bot python -m app.migrate_schema
```

## Важливо

- Не додавайте токен до `app/main.py`, `README.md` або `.env.example`.
- Запускайте лише один процес бота одночасно. Інакше Telegram поверне помилку
  конфлікту long polling. Перед Docker-запуском зупиніть локальний запуск.
- Якщо токен розкрито, перевипустіть його через `/token` у `@BotFather` і
  замініть значення лише у локальному `.env`.

## Тести API

Встанови `requirements-dev.txt` у віртуальне середовище. Для тестів потрібен
окремий PostgreSQL з базою `finance_test` і змінною `TEST_DATABASE_URL`
у форматі `postgresql+psycopg://.../finance_test`. Тести створюють окрему
тимчасову схему для кожного сценарію та прибирають її після завершення.
Вони не читають `DATABASE_URL` і не додають тестових операцій до Neon.

```bash
.venv/bin/python -m pip install -r requirements-dev.txt
.venv/bin/python -m unittest discover -s tests -v
```

Покрито збереження й читання операцій, підсумки, ізоляцію користувачів,
валідацію полів, одночасне створення категорії, відкат при помилці коміту,
сумісність із ботом і міграцію дат.
Окремо перевіряється видалення доходів і витрат, нові підсумки, перевірка
власника, повторні DELETE-запити та відкат при помилці коміту видалення.
